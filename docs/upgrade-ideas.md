# 大升级构想(未定稿)

> 2026-10-29 的讨论记录,不是开工计划。目标是从"手机遥控一台 Mac"升级到"任意设备控制任意设备":手机控电脑、电脑控手机或电脑、手机控手机,外加看屏幕(类似 ToDesk、网易 UU、向日葵)和电脑之间共享键鼠(类似 Deskflow,见 [deskflow-reference.md](./deskflow-reference.md))。改动接近重写,先记下来,慢慢考虑。

## 一、能做到什么

| 控制端 → 被控端 | 看屏幕 | 控制 | 被控端用什么 |
|---|---|---|---|
| 任意设备 → Windows / Mac / Linux | ✓ | ✓ | 采集用系统接口;控制靠模拟键鼠(Windows SendInput / Mac CGEvent / Linux XTest,Wayland 走 portal) |
| 任意设备 → 安卓 | ✓ | ✓,有限制 | 看:MediaProjection;控:无障碍服务 `dispatchGesture` |
| 任意设备 → iPhone | ✓,有限制 | ✗ | 看:ReplayKit 系统级录屏扩展;控:苹果不给第三方注入触控的接口 |

控制端在哪个平台都没问题:本质就是显示视频,再把鼠标或触摸转换成指令发出去。

## 二、手机当被控端的限制

**安卓**

- **看屏幕**:每次开始共享都要用户点同意。Android 14 起授权不能复用,还必须先启动 mediaProjection 类型的前台服务。Android 15 默认只共享单个应用,要引导用户选"整个屏幕"。
- **控制**:普通应用没有注入触摸的接口,只能用无障碍服务模拟点击和滑动,返回、主页等用全局操作,文字用输入法或无障碍填入。手感比电脑上模拟鼠标差,连续拖动要分段接上。
- **开启门槛**:
  - Android 13 起,网页下载安装的应用要先在应用信息里手动解除"受限设置",才能打开无障碍;
  - 国产 ROM 会杀后台、自动关掉无障碍;
  - 上架 Google Play 要单独申报无障碍的用途。
- **黑屏**:开了 FLAG_SECURE 的界面(银行类、密码输入框),采集到的是黑屏。
- **另一条路**:像 scrcpy 那样走 ADB 无线调试,能拿到真正的注入权限,手感好得多,但要用户打开开发者选项。可以作为"高级模式"。
- 纯血鸿蒙不是安卓,不在这张表里。

**iPhone**

- **看屏幕**:用户每次要从控制中心手动开始"屏幕广播"。广播扩展的内存上限很低(约 50MB),编码必须用硬件。
- **控制**:做不了。市面上远控 iPhone 的方案一般要外接硬件模拟蓝牙鼠标,不考虑。

## 三、ToDesk 是怎么控制安卓的(2026-10-29 查的公开资料)

结论:**录屏看画面 + 无障碍服务模拟点击,不用 root**,和上面的方案一样。iPhone 被控只能看,不能远程点击。官网下载有防机器人校验,没有拿到安装包,所以没核对它实际申请的权限。

- **被控端要给的权限**:电话、录屏、辅助功能、电池白名单;打开"允许远程本设备"并选"控制模式",主控端的模式必须一致,否则提示"访问被拒绝"。
- **要求 Android 8.0 以上,两台设备必须登录同一个 ToDesk 账号**。
- **不支持无人值守**。官方原话是"由于安卓系统限制……app长时间后台会被清理进程",只能靠自启动、锁定进程来降低被杀的频率。
- 别的应用占用录屏时,远程画面会变白,要重新打开 ToDesk。
- 被控端会弹风险提示;输入支付密码时,主控端画面变黑。
- 安卓被控是付费功能,按设备数量计费。
- 电脑的鼠标键盘怎么转换成手机上的触摸:官方页面没有说明,需要自己设计。

**业内其他做法**(向日葵官方资料):

| 方式 | 原理 | 适用范围 |
|---|---|---|
| Root | 拿到 root 后直接注入输入事件 | 只适合愿意 root 的人 |
| 厂商签名插件 | 用手机厂商的系统签名打包,装上后获得系统级权限,免 root | 要和厂商合作,个人项目做不了 |
| 三星免 root | 三星部分机型自带支持 | 只限这些机型 |
| 蓝牙外接硬件(向日葵 UUPro) | 硬件模拟蓝牙鼠标去操作手机 | 要买硬件 |

**值得照搬的**:

- 引导页手把手带用户开权限,各品牌的电池白名单分别给说明;
- Android 15 提示选"整个屏幕";
- 被控端风险提示;
- 不承诺无人值守;
- 默认只允许自己账号的设备控制安卓。

## 四、技术方向(倾向,未验证)

- **全平台统一用 Flutter + `flutter_webrtc`**:
  - 它在安卓上能直接用 MediaProjection 采集屏幕,在 iOS 上能接录屏广播扩展,在桌面上也能采集屏幕。采集、编码、传输、解码、显示都交给 libwebrtc,五个平台一套代码。
  - 跨公网的打洞和中转(STUN/TURN)也是 WebRTC 现成的。
- **只有输入注入按平台写原生代码**,做成 Flutter 插件:
  - Mac:现有的 Swift `MouseController` / `KeyboardController` 基本能直接搬进来;
  - Windows:C++;
  - 安卓:Kotlin 无障碍服务。
- **Rust 不是必需的**。等做电脑之间共享键鼠、或者要复用 LocalSend 的 core 做文件传输时再引入。
- **要先验证**:`flutter_webrtc` 在桌面端的屏幕采集好不好用(Windows 和 Mac 一般没问题,Linux 和 Wayland 不确定),能不能用上硬件编码。如果画质或延迟达不到远控的要求(libwebrtc 是为视频会议调的,不是为远程桌面),电脑被控端改用 Rust 自己采集编码,参考 RustDesk。
- **不选的那条路**:像 RustDesk 那样自己定协议。控制力更强,但手机端的硬件解码和渲染都得自己写。

## 五、跨公网

ToDesk、UU、向日葵的核心价值在跨公网,背后是大量中转服务器。手上的 2 核 2G VPS 扛不住视频中转(桌面画面动起来常见要几 Mbps,具体要实测)。分三步走:

1. 先只做局域网:不需要服务器,延迟最低;
2. 跨公网先尝试 P2P 打洞(STUN):能打通的情况下,视频不经过服务器;
3. 打不通再走中转(自建 TURN 并限速)作兜底;也可以让用户自己部署中转。

## 六、安全底线

能看屏幕又能控制,等于完全接管这台设备。"无障碍 + 录屏"也正是电诈和木马应用的标准组合,系统、手机厂商、安全软件都会重点盯。下面这些要做成默认行为,不能做成可选项:

- 配对或绑定账号,连接全程加密(做法见 [deskflow-reference.md](./deskflow-reference.md) 第一节);
- 被控时始终有醒目的提示,并且能一键断开;
- 不是自己的设备来连,必须在被控端点确认;
- 手机被控默认不开"无人值守"。

## 八、粗略路线

- **M0 · 换架构**:Flutter 同时覆盖手机和桌面;配对、加密、信令;触控板功能搬到 Windows 和 Mac。
- **M1 · 局域网,Windows 被控**:手机和电脑都能当控制端,顺带验证 `flutter_webrtc` 桌面端的画质和延迟。
- **M2 · 安卓被控**:先看屏幕,再做无障碍控制;ADB 高级模式作为可选。
- **M3 · 跨公网**:信令服务器、打洞、TURN 中转兜底。
- **M4 · 电脑之间共享键鼠**。
- **以后再说**:iPhone 被看、文件传输、剪贴板、声音、多显示器。
